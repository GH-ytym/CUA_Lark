# CUA 触发与执行边界规范

## 1. 概述

本文档定义了基于视觉大模型的飞书CUA（Computer-Use Agent）系统的触发条件、执行边界、安全规则以及动作能力范围，为CUA系统的稳定可靠运行提供明确的规范依据。

***

## 2. CUA 接管的明确边界

当飞书CLI接口调用出现以下任意错误场景时，系统将自动切换到CUA视觉操作模式接管任务执行：

| 接管触发类型                     | 触发场景说明                              | 接管逻辑                                  |
| -------------------------- | ----------------------------------- | ------------------------------------- |
| RATE\_LIMIT（接口调用频率超限）      | 短时间内大量调用飞书API达到限流阈值，CLI无法继续正常工作     | 切换到CUA视觉操作模式，通过模拟用户手动操作完成任务，避开API限流限制 |
| API\_UNSUPPORTED（接口功能不支持）  | 当前需要执行的操作没有对应的飞书开放API，或者API权限不足无法调用 | 切换到CUA视觉操作模式，通过界面交互完成CLI无法实现的功能       |
| PERMISSION\_DENIED（接口权限不足） | 当前账号没有调用对应API的权限，或者Token过期/失效       | 切换到CUA视觉操作模式，使用已登录的桌面客户端权限完成操作        |
| API\_ERROR（接口内部错误）         | 飞书服务端返回未知错误，API调用连续失败超过重试次数         | 切换到CUA视觉操作模式，绕过故障的API接口完成任务           |

***

## 3. CUA 放弃执行的安全红线

CUA视觉操作模式下出现以下任意场景时，将立即放弃当前任务执行，避免无效操作或错误执行：

| 放弃触发类型                         | 触发场景说明                                     | 处理逻辑                        |
| ------------------------------ | ------------------------------------------ | --------------------------- |
| LOW\_CONFIDENCE（界面识别置信度过低）     | 视觉大模型对当前屏幕界面的识别置信度低于设定阈值（如<0.7），无法确定界面元素含义 | 停止执行，返回人工介入请求，避免误操作         |
| TIMEOUT（操作执行超时）                | 单个操作步骤执行时间超过设定阈值（如30秒），或整个任务执行时间超过总时长限制    | 终止任务执行，返回超时错误，避免无限等待        |
| INTERFACE\_CHANGED（界面意外变化）     | 操作过程中界面发生预期外的变化（如弹窗、跳转至未知页面），与任务规划的界面流程不符  | 停止执行，重新识别界面或请求人工确认          |
| MAX\_RETRY\_EXCEEDED（操作重试次数超限） | 同一个操作步骤连续失败超过最大重试次数（如3次），仍无法成功完成           | 终止任务，返回执行失败，避免重复无效操作        |
| SECURITY\_RISK（检测到安全风险）        | 操作可能涉及敏感信息（如密码输入、删除重要数据等），或识别到钓鱼/风险界面      | 立即停止执行，返回安全风险警告，必须人工确认后才能继续 |

## 4. 目前支持的 Windows 动作原语列表

CUA系统在纯Windows环境下已封装以下基础动作原语：

| 原语方法                                                                 | 功能说明                     | 参数列表                                                             | 返回值                          |
| -------------------------------------------------------------------- | ------------------------ | ---------------------------------------------------------------- | ---------------------------- |
| `focus_and_maximize(app_name: str = "飞书")`                           | 将指定应用窗口强制置顶并最大化          | `app_name`: 应用窗口名称，默认为"飞书"                                       | `bool`: 操作成功返回True，失败返回False |
| `safe_click(x: int, y: int, clicks: int = 1, interval: float = 0.2)` | 安全点击方法，自动处理DPI缩放转换       | `x`: 原始横坐标`y`: 原始纵坐标`clicks`: 点击次数，默认1次`interval`: 多次点击间隔，默认0.2秒 | `None`                       |
| `safe_input(text: str)`                                              | 安全输入中文文本，使用剪贴板复制粘贴方式避免乱码 | `text`: 需要输入的文本内容                                                | `None`                       |
| `save_state_for_backtrack(current_state: Dict) -> Dict`              | 保存当前状态用于回溯，防止引用污染        | `current_state`: 当前状态字典                                          | `Dict`: 拷贝后的状态字典，可安全存储用于回溯   |

## 5. 纯 Windows 环境下的潜在风险场景

### 5.1 DPI 缩放问题

- **风险描述**：Windows系统不同DPI缩放比例（如125%、150%、200%）会导致截图坐标与实际屏幕坐标不匹配，点击位置偏移
- **现有应对**：已预留`DPI_SCALE_FACTOR`全局配置项，可根据系统实际DPI设置调整换算系数
- **优化建议**：后续可新增自动获取系统DPI缩放比例的能力，无需手动配置

### 5.2 突发弹窗抢占焦点

- **风险描述**：操作过程中系统弹窗、广告弹窗、消息通知等意外弹出，抢占窗口焦点，导致操作作用到错误窗口
- **现有应对**：界面意外变化检测机制会识别到非预期界面，触发放弃执行逻辑
- **优化建议**：新增弹窗自动关闭/忽略逻辑，针对常见系统弹窗可设置白名单自动处理

### 5.3 剪贴板内容覆盖问题

- **风险描述**：`safe_input`方法使用剪贴板进行中文输入时，会临时覆盖用户剪贴板内容
- **现有应对**：已实现剪贴板内容自动恢复机制，输入完成后会还原用户原始剪贴板内容
- **注意事项**：极端情况下如果程序异常中断，可能导致剪贴板内容无法恢复

### 5.4 窗口标题匹配问题

- **风险描述**：`focus_and_maximize`方法基于窗口标题匹配应用，当飞书窗口标题变化（如打开特定文档、聊天窗口）可能导致匹配失败
- **现有应对**：支持自定义窗口名称参数，可根据实际场景调整匹配关键词
- **优化建议**：新增基于进程名、窗口类名等多维度窗口匹配能力

### 5.5 用户操作打断风险

- **风险描述**：CUA执行过程中用户手动操作鼠标键盘，会与CUA操作产生冲突，导致执行失败或误操作
- **现有应对**：操作超时、重试次数超限机制会终止异常执行流程
- **优化建议**：新增用户操作检测能力，检测到用户主动操作时自动暂停CUA执行
